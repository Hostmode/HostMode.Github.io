# Event debrief

Turn one finished event into better templates for the next one.

## Gather

- The run-of-show record (Run of show → "Copy for the debrief"): what ran late, by how much, and why.
- Issue flags vendors raised on the vendor page, and whether they were fixed.
- Feedback from the host, client and guests (Feedback tab), and any ticket from that night.
- Pull-list check-in: missing or damaged pieces and photos.
- The planner's own notes. Ask: "What would you do differently?"

## Write the debrief

1. **What went well** (keep doing): 3 bullets at most.
2. **What slipped:** each late step with minutes late and the likely cause.
3. **Changes for next time**, each tied to a place in Host Mode:
   - Timeline: "Give dinner 15 more minutes" → the event type's moments or the planner's template.
   - Checklist: "Confirm the DJ's arrival two days out" → the client checklist template.
   - Inventory: "Pack 10% extra napkins" → the pull list or reorder level.
   - Vendors: "Caterer needs the kitchen 90 minutes early" → their vendor page note.
4. **Thank-yous** worth sending (vendors, teammates).

## Rules

- Facts from the record, not guesses. If the cause of a delay isn't known, say so.
- No blame in the wording; describe what happened.
- Keep guests' names out of anything shared beyond the planner.
- Offer to draft the template changes; the planner approves them.

## Host Mode rules that always apply

- Plain, friendly words written for planners and hosts. No technical jargon.
- Never name a competitor or another app in anything public. Say "other apps". Unfinished features are "coming soon".
- Host Mode only tracks money. It never takes or sends payments.
- Never put customer data in the repo (it is public). Use the demos for examples.
